Adding a place — how it lands in a city

You never type the city. When a Google result is saved, Google's address data is read and the place files itself under that city. The screens below make this visible, and give a way to correct it when Google is wrong.
Where the city comes from
Google Places result → address components → locality = city ("Shanghai"), country = "China", sublocality = district ("Xuhui")
If locality is missing → use administrative_area_level_1 (province / state)
If still missing → ask you (screen 4)
This already exists in the current backend. What is missing today is showing it to you before you tap Save, and letting you fix it afterwards.

Summary
Normal case (95%+): tap Save, city is filled by Google, you see it in the row and the toast. Zero extra steps.
Google returns a district instead of the city: tap "Wrong city?" in the toast, pick from one short list.
Google returns nothing: app asks before saving, suggests nearest cities.
Any time later: place ⋯ menu → "Change city".
